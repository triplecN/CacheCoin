CacheCoin (CCCN) Windows package - provenance of every file
===========================================================

This file says where each file in this package came from and how to check it.
No file here is anonymous. A file not covered by this document is a defect;
report it as described in SECURITY.md.

The package version and the SHA-256 of every packaged file are in version.json.
SHA256SUMS.windows.txt lists the same hashes as text, and
SHA256SUMS.windows.txt.asc is the offline GPG signature over that list.

How to verify
-------------
1. Run "Verify Download.cmd". It checks version.json, every file hash and the
   checksum list, and the release signature when the .asc file is available
   (it looks in the package folder and in the folder above it) and GnuPG is
   installed. When the signature cannot be checked it says so instead of
   claiming authenticity.
2. Or by hand:
       sha256sum -c SHA256SUMS.windows.txt
       gpg --verify SHA256SUMS.windows.txt.asc SHA256SUMS.windows.txt
   The release key fingerprint is published with the release (see VERIFY.txt).
3. The launcher checks version.json on every start and refuses to run when a
   listed file is missing, modified, or when a program file is not listed.
4. The strongest source anchor is the patch fingerprint below: it identifies
   the exact consensus source this package was built from.

CacheCoin.exe (the window; present when the package was built with the GUI)
  Built from the CacheCoin GUI source tree with build.sh (Linux/macOS) or
  build_det.ps1 (Windows). Both use the Roslyn compiler with -deterministic;
  two consecutive runs of build_det.ps1 produced a byte-identical file for the
  packaged build. Its PE header time is a content-derived value, not a build
  timestamp. License: MIT; the embedded fonts are under the SIL Open Font
  License (texts in docs\licenses\).

Text files from this repository (MIT)
-------------------------------------
launcher\CacheCoin.ps1, tools\*.ps1, the .cmd entry points, docs\**,
README-Windows.txt, LICENSE, TOR-PIN.txt. They ship as readable source; the
NewWallet tool compiles a small embedded C# helper at runtime (Add-Type).

Generated files
---------------
version.json and SHA256SUMS.windows.txt are written by windows\build_package.sh.
SHA256SUMS.windows.txt.asc is created offline with the release GPG key and is
published next to the ZIP, not inside it. PROVENANCE.txt is this document.

Build metadata and honesty notes
--------------------------------
- PE header times in this package: the node executables carry 1970-01-01 (the
  linker omits the timestamp); CacheCoin.exe carries a content-derived value;
  the Tor executables are normalized by the Tor Project (1970-01-01). No
  packaged file's content carries the packager's local time. ZIP entry
  timestamps depend on the zip tool used at release time; the detached
  signature carries its creation date.
- Bit-for-bit reproducibility is not implemented for the node executables.
  The GUI executable is deterministic.
- Known gaps: the MinGW-w64 runtime is statically linked into the executable
  and its license text is not redistributed in the package (the pluggable
  transports' multi-license lists ship inside the Tor bundle's own text
  files).
